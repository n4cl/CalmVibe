# Issue ルール

## 参照タイミング
- Issue を作成・更新する直前に参照する

## 基本方針
- `.github/ISSUE_TEMPLATE/` から目的に合うテンプレートを選ぶ
  - 不具合報告: `bug_report.md`
  - 機能追加・改善提案: `feature_request.md`
- 本文はテンプレートの見出しをそのまま使い、省略せずに埋める
- タイトルはテンプレート本文の見出しではなく、変更対象と論点が先に分かる形にする
- タイトルと本文は、その Issue で扱う Git 管理下の対象だけに言及する
- 差分外の将来案や無関係な話題を広げすぎず、必要な範囲に絞る

## タイトル方針
- 変更対象や論点を先に書く
- 検討事項を含む Issue でも、背景説明だけをタイトルにしない
- 例:
  - `AGENTS.md に Issue テンプレート利用ルールを追加する`
  - `セッション画面で停止後に BPM 表示が更新されない`

## 本文方針
- 背景、課題、解決案、完了条件を分けて書く
- ルールや運用の Issue では、採用案と代替案の両方を書く
- 関連するテンプレートやドキュメントがあれば、Git 管理下のパスで示す
- 課題や解決案は、その Issue で変更対象になり得るファイル、ルール、機能に閉じて記述する

## 補足
- タイトルに `feat:` や `fix:` などの prefix は付けない
- これは `.github/ISSUE_TEMPLATE/` のルールに従う
