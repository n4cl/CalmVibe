# PR ルール

## 参照タイミング
- Pull Request を作成・更新する直前に参照する

## 基本方針
- PR 本文は `.github/PULL_REQUEST_TEMPLATE.md` をそのまま使う
- タイトルは prefix を付けず、変更対象と変更内容が先に分かる形にする
- PR はレビュー可能な粒度に保つ
- 1 つの PR に、独立してレビュー・マージできる複数の変更を混ぜない
- PR のタイトルと本文は、Git 管理下の変更対象を中心に書く
- Git 管理下にないローカルファイル、ローカルパス、一時ファイルのようなローカル専用情報には言及しない
- Git の履歴、Issue、PR から追跡できない経緯や判断には言及しない
- 動作確認には、実際に実行したコマンドや確認結果を書く

## 補足
- AI エージェントが PR を作る場合も、人間がそのまま再利用できる Markdown を出力する
