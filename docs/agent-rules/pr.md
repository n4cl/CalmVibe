# PR ルール

## 参照タイミング
- Pull Request を作成・更新する直前に参照する

## 基本方針
- PR 本文は `.github/PULL_REQUEST_TEMPLATE.md` をそのままテンプレートとして扱い、見出しと記載方針に沿って記述する
- タイトルは本文の見出しに引っ張られず、変更対象と変更内容が先に分かる形にする
- タイトルに背景説明や抽象的な検討表現だけを書かない
- タイトルと本文は、その PR に含まれる Git 管理下の変更対象だけに言及する
- 差分に含まれない将来案、別作業、無関係な背景説明は本文へ混ぜない

## タイトル方針
- 変更対象と変更内容を先に書く
- 例:
  - `Expo 54 系 patch 依存を更新`
  - `AGENTS.md に Issue / Commit 運用ルールを追加`
- 避けたい例:
  - `方針を整理する`
  - `背景を整理する`
  - `運用を見直す`

## 本文方針
- `.github/PULL_REQUEST_TEMPLATE.md` の見出しを維持する
- 原則は Git 管理下のファイルや概念のみを書く
- 該当しない項目は `該当なし` と明記する
- 動作確認には、実際に実行したコマンドや確認結果を書く
- 変更対象の説明は、PR に含まれるファイルや概念に閉じて記述する

## 補足
- AI エージェントが PR を作る場合も、人間がそのまま再利用できる Markdown を出力する
