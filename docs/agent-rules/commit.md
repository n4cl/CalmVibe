# Commit ルール

## 参照タイミング
- Git コミットを作成する直前に参照する

## 基本方針
- コミットメッセージは `prefix: 日本語メッセージ` 形式を基本候補として扱う
- prefix は変更の種類を表し、本文は日本語で更新の目的を簡潔に書く
- 最優先は、「何のための更新か」が分かること
- そのうえで、そのコミットに含まれる Git 管理下の変更対象だけに言及する
- 「何を変えたか」だけで終わらず、目的が伝わる表現を選ぶ
- 差分に含まれない背景説明、将来案、別 Issue の話題はコミットメッセージに含めない

## 形式
- `prefix: 日本語メッセージ`
- 例:
  - `feat: 履歴一覧画面にフィルタ機能を追加`
  - `fix: セッション停止後にタイマーが残る不具合を修正`
  - `docs: PR テンプレート利用ルールを追記`
  - `chore: Expo 54 系 patch 依存を更新`
  - `refactor: セッション設定のバリデーション処理を整理`
  - `test: SQLite Repository の回帰テストを追加`

## prefix の案
- `feat`: 機能追加
- `fix`: 不具合修正
- `docs`: ドキュメント更新
- `chore`: 雑務的な更新、依存更新、設定調整
- `refactor`: 振る舞いを変えない設計・実装の整理
- `test`: テスト追加、テスト修正、検証コードの改善

## 運用メモ
- ファイル名の列挙ではなく、機能、設定、文書、依存関係などの Git 管理下の概念を簡潔に表現する
- 1つのコミットに複数の独立した話題を混ぜない
- 一時的な作業メモのような曖昧なメッセージは避ける
